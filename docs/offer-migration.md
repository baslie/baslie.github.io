# Перенос оффера на offer.roman-purtow.ru

Решение принято 14.10.2026, перенос — в следующей сессии.

## Решение

Воронку `/offer/1–4` выносим из этого репозитория в отдельный проект и отдельный репозиторий.
Её выкладываем на российский хостинг с PHP и MySQL на поддомене `offer.roman-purtow.ru`.
Основной сайт `roman-purtow.ru` остаётся на GitHub Pages без изменений, кроме удаления оффера и редиректов.

Рассматривали и более лёгкий вариант: оставить оффер здесь, а на хостинг вынести только `form.php`.
Роман выбрал полный перенос.

## Почему

1. **Секрет в открытом коде.** `src/scripts/offer-form.ts` шлёт заявки прямо из браузера в Telegram Bot API.
   Токен бота лежит в клиентском коде, а репозиторий публичный. Токен даёт полный контроль над ботом,
   а не только отправку сообщений.
2. **152-ФЗ, локализация.** Персональные данные (имя, телефон/Telegram) первично записываются в Google Sheets
   (Apps Script) и в Telegram, то есть за рубежом. Закон требует сначала записывать их в базу в России.
3. **Без Google и Telegram.** Роман хочет приём заявок, который работает в России и не зависит от этих сервисов.

## Целевая схема

```
offer.roman-purtow.ru (российский хостинг: Beget / Timeweb / REG.RU — выбрать)
├── статика оффера (Astro build → загрузка на хостинг)
└── form.php → MySQL на хостинге + письмо Роману (SMTP Яндекс Почты, пароль приложения)
```

- DNS: A-запись `offer` → IP хостинга. Записи основного домена не трогаем.
- SSL: Let's Encrypt на хостинге.
- Форма и обработчик на одном домене, CORS не нужен.
- Пароли SMTP и БД — только в конфиге на сервере (вне git или в `.gitignore`), не в клиентском JS.
- `form.php`: валидация, honeypot-поле от спама, ограничение длины полей, JSON-ответ, чтобы форма знала реальный результат.
- Деплой: GitHub Actions → `npm run build` → загрузка `dist/` и `form.php` по FTP/SSH (что даст хостинг).

## Что сделать в этом репозитории после переноса

1. Удалить файлы оффера (таблица выше), неиспользуемые стили и картинки.
2. Редиректы со старых адресов `roman-purtow.ru/offer/N/` на `offer.roman-purtow.ru/...`.
   Ссылки с UTM уже разосланы, а GitHub Pages не умеет серверные редиректы. Нужны страницы-заглушки
   с JS-редиректом, который переносит `location.search` (meta refresh query-строку теряет).
   Сейчас в `astro.config.mjs` есть редирект `'/offer': '/offer/1/'` и `/offer/` в `EXCLUDED_PREFIXES` sitemap.
3. Проверить ссылки на `/offer/` в `src/components/archive/OfferAbout.astro`, `OfferHero.astro`, `src/pages/archive/offer-02.astro`.
4. Убрать ключ `o3_utm` из `localStorage`, если его пишет что-то на основном сайте.
